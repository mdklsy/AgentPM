# AgentPM 与 Jira 的基础功能差距盘点

> 2026-11-10，M5.5 体验整改时梳理。目的：明确"对标商业版"还差哪些基本盘，按优先级排进 roadmap。
> **2026-11-10 更新：P0×7 + P1×8 已在 M6 全部交付**（测试报告见 [test-report-m6.md](./test-report-m6.md)）；下表"落点"列保留原始规划。
> 判定基准：Jira Cloud 标准版的核心日常能力。AgentPM 已有的差异化能力（MCP、agent 审计、审批闸门、PM 替身、信誉分）不在本文讨论范围。

## 现状快照（已具备）

多项目/成员角色、issue 全生命周期（5 类型/优先级/标签/父子/关联/关注）、可校验工作流状态机、并发安全 claim、Sprint（排期/启停/收尾退回）、燃尽图（审计流重建）、速率、评论、活动流、站内通知、Webhooks（HMAC）、搜索过滤、REST+OpenAPI、MCP 双传输、回归矩阵、审批队列、监控中心。Web UI 覆盖以上全部。

## P0 —— 基本盘缺口（v0.x 应补齐）

| 缺口                 | 说明                                                                                                         | 建议落点               |
| -------------------- | ------------------------------------------------------------------------------------------------------------ | ---------------------- |
| **附件文件上传** ✅         | 目前仅 URL 型附件（Attachment 表已有 mimeType/sizeBytes 字段，无上传端点）；头像上传（M5.5）可复用其存储路径 | M6：本地磁盘/S3 双后端 |
| **CSV 导出/导入** ✅        | issue 列表导出 CSV；CSV 批量建卡（Jira 迁移的基本替代）                                                      | M6                     |
| **评论 @提及** ✅           | `@name` 解析 → 定向通知；当前评论只通知 watcher                                                              | M6                     |
| **批量操作** ✅             | 看板/列表多选 → 批量改状态/指派/优先级/移 sprint                                                             | M6                     |
| **"我的工作"跨项目视图** ✅ | 跨项目聚合：指派给我的/我关注的/@我的；目前一切视图都局限单项目                                              | M6                     |
| **邮件通知渠道** ✅         | 站内信之外的最基本外呼渠道（webhook 可自己接 IM，但邮件是零集成成本默认项）                                  | M6                     |
| **管理后台** ✅             | 实例级设置页（用户管理已有 /team；缺 agent 策略默认值、实例信息）                                            | M6.x                   |

## P1 —— 对标 Jira 核心体验

| 缺口                       | 说明                                                                                  |
| -------------------------- | ------------------------------------------------------------------------------------- |
| **自定义字段** ✅                 | Jira 招牌能力。建议 JSON 字段 + 项目级字段定义（文本/数字/日期/单选），看板卡片可显示 |
| **版本（Release/fixVersion）** ✅ | issue 归属版本、版本发布页、按版本统计；Sprint 之外的第二维度                         |
| **工作流编辑器 UI** ✅            | 数据模型已支持任意状态/转移，缺管理界面（增删状态、拖转移线）；当前只能用默认流       |
| **保存的过滤器** ✅               | 搜索条件命名保存 + 侧栏快捷入口 + 订阅（定期推送结果）                                |
| **敏捷报表扩展** ✅               | 控制图（周期时长）、累积流图、速率趋势（跨 sprint）、Epic 进度报告                    |
| **富文本描述/评论** ✅            | Markdown 渲染起步（评论已是纯文本，缺渲染与编辑器）                                   |
| **工时跟踪** ✅                   | 估计工时/登记工时/工时报表（team 以 story points 为主时可降级）                       |
| **仪表盘** ✅                     | 可拼装小工具的首页（按项目/按人的图表卡）                                             |

## P2 —— 体验与生态

- 自动化规则（Jira Automation）；AgentPM 可用 agent+MCP 覆盖大部分场景，但"无代码规则"仍是刚需
- i18n 中英双语（M6 已列）
- 键盘快捷键 / 命令面板（⌘K 全局跳转）
- Git/CI 集成：commit 关联 issue、PR 状态回写（webhook 入站 + MCP 出站可拼装）
- issue 模板、子任务层级>1 层、跨项目 issue 移动
- 移动端适配、PWA
- 组件（Component）模块、issue 级安全方案、字段级权限
- 数据备份/导出全量、审计日志导出（合规场景）

## 刻意不做的

- Jira Service Management（工单/SLA/客户门户）——超出项目管理定位
- 复杂权限方案编辑器（字段级/issue 级安全）——开源单实例场景收益低
- Portfolio/高级路线图（跨项目 timeline）——等核心盘稳固后再议
